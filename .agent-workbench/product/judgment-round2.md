**H1 · fatal — v1 inversion: the verifier is now locked behind the runtime it was supposed to sell — "ui check lints fx verbs against the closed catalog" (line 40)**
Round-1 H6: "The one piece with standalone value is the agent-side verification tooling aimed at existing stacks" — and its test (ship shot/tree for React, measure adoption) was days-scale and free. prototype-runtime.md contains no result from that test; instead the verifier became a feature of a new runtime whose only differentiator (see H4) is the verifier. That is a mutual dependency with no standalone entry: nobody adopts a runtime to get a linter, and the linter can't exist alone because the closed vocabulary requires the runtime. Same ship-all-three-or-nothing shape H6 flagged, now at architecture level. The design is fixable by resequencing, which is why this gates code rather than kills the idea: prove verification demand before building the thing it verifies.
Test: (1 day) run round-1 H6's test — shot/tree skill on existing React projects, measure operator retention. (2–3 days, zero runtime) build ui check as a linter over a closed-verb subset of *Alpine's* attributes. If the linter demos well on Alpine, the runtime adds no verifiable capability; if it can't be made sound over Alpine's free-JS attributes, that is the first real evidence the closed catalog matters. Either result redirects weeks of work for the price of a linter.

**H2 · serious — the isomorphism is false at subscription time — "the DOM tree becomes the prototype chain of application state" (line 11)**
Prototype lookup is dynamic per access; signal subscription is captured once at bind time. Reparent a bound element — an operation agents perform constantly — and dynamic scope resolution and captured subscriptions disagree. Either re-resolve on mutation observation (an effect-ownership complexity iceberg, thrash risk) or freeze scope at bind (the headline isomorphism is then marketing). Same root causes the rest of the elided machinery: subscriber Sets on root-declared signals (`document.ui.signal('count', 0)`, line 19) outlive removed DOM with no disposal model (Solid owners / Vue effect scopes are exactly the 40 lines that aren't there); ancestor re-declaring a signal name is dynamic scoping — the semantics the industry abandoned — and it makes line 40's "ancestor lookup is statically approximable" unsound under reparenting and shadow boundaries (approximation = false positives on generated scopes). Array mutation is silently undefined: a get/set cell does not notify on `push`; the honest rule is immutable replacement, but the doc never states it.
Test: not days — a spec-accuracy fix. Rewrite the claim to state (a) merge semantics on shadowed names, (b) what reparenting does to an existing bind, (c) the disposal model, (d) the mutation rule for collections. If any of the four has no answer, the core is a demo, not a runtime.

**H3 · serious — gravity slide: round 2 answers a weaker H1 than the one that killed round 1 — "This rides HTML's gravity instead — older and larger" (line 38)**
Round-1 H1 killed the ambition on adopter incentives (market.md §5: v0/Lovable/Cursor monetize by emitting React into stacks humans accept), not on syntax friction. HTML-gravity addresses syntax friction only. And even the syntax claim is untested: Alpine's attribute style is already in every agent's training data — if agents reached for attribute-based reactivity when it fit, the gravity argument would already have evidence. The doc's own concession ("Coexist, never replace", line 41) is consistent with round 1's verdict, so the ambition question is nominally settled; what is not settled is who mandates the attribute grammar, which is H1's adopter-incoherence untouched.
Test (hours, zero code): give a real agent 10 single-file interactive-page tasks with no skill installed and log what it emits. If it writes vanilla JS or React-via-CDN rather than attribute reactivity it already knows, "HTML gravity" is not load-bearing for agents and distribution is as dead as round 1 said. This and H1's test should run before any runtime code.

**H4 · serious — analyzability survived, but conditional and decaying — "ui:fx=\"click: set count+1; call POST /cart\"" (line 38)**
ui check can still work — but only if the attribute grammar is a whitelist-AST expression subset run by a hand-written interpreter, never eval'd: parse, walk, allow known node types, reject the rest. That is a real, buildable design — and it is the round-1 grammar-budget problem re-instantiated: the operator whitelist, `$event` shape, and `call`'s response→signal mapping all need specification, and every addition widens the attack and hallucination surface. Meanwhile the JS API (`['set', 'count', n => n + 1]`, line 25) takes real closures that check cannot inspect at all, so verified coverage equals the fraction of behavior expressed in attributes — round 1's H3 boundary migration, unchanged in kind. Note also line 39's claim "Verbs compile to verified platform APIs": `call` optimistic/rollback is "set-then-undo on signals" — their own runtime code, not a platform API; popover/commandfor and Navigation API are genuinely verified Baseline (browser-apis.md lines 14–15, 24), and moveBefore's Safari gap is honestly owned (browser-apis.md line 20) — the compile-target story is real but thinner than claimed.
Test (1 day, no code): write the expression subset spec (allowed AST nodes, $event shape, response mapping) and manually express 10 real screens' behavior in it. The fraction that fits is the product's true verification claim.

**H5 · serious — security: same-document execution regresses in the only live distribution lane — "this form reintroduces executable strings" (line 49, self-flagged)**
The no-eval interpreter from H4 is also the XSS answer — one design decision serves both — so the happy path is answerable. Two gaps remain. (a) `call POST /cart` has no auth/CSRF story: same-origin cookie fetches by default, no token concept in the verb, and the verb makes state-changing calls one token easy for an agent that doesn't know the backend's rules; htmx precedent says survivable (server-side checks, CSP, explicit allowlist rule), but it must be a stated policy, not an omission. (b) The lane where agent-authored HTML actually ships today is MCP-UI/MCP-Apps — sandboxed iframes, chosen *because of* this hazard (market.md §1: hosts render in sandboxed iframes). Same-document execution on Element.prototype is a sandbox regression precisely there. Survivable in the prototype lane; disqualifying if MCP embeds become the target lane.
Test (1 paragraph + 1 hour): write the CSP/allowlist/Trusted-Types policy (Trusted Types is Baseline 2026, browser-apis.md line 22), then run one prompt-injection test where rendered content tries to influence emitted fx attributes.

**Survivable (name and move on):** Tier-3 primitives + statecharts carried "unchanged" into scope (line 34) re-imports round 1's three-products problem — v1 is one product only if the lane is single-file prototypes and Tier 3/statecharts/SSR-parity are explicitly roadmap; prototype patching version conflicts (two script loads vs a frozen root — document it); cross-document/derived-signal ownership (defer, the lane doesn't need it); scheduler at 10k bindings (defer, honest as stated).

**What is the delta vs Alpine, said plainly:** no user-visible capability. Alpine does x-data ancestor scoping, attribute reactivity, event handlers today. The falsifiable delta is exactly two things — a sound linter (requires the closed vocabulary, which requires the runtime — H1) and platform-native compile targets for a subset of verbs (real, verified, thin: progressive enhancement, not capability). TC39 Signals will commoditize the `sig()` cell from underneath (doc concedes, line 45), which again points the defensible layer at verbs+check, i.e., at H1's sequencing question, not the runtime's 40 lines.

---

**Riskiest assumption (the one thing that kills it if wrong):** round 1's assumption in new clothes — that agent gravity follows syntax familiarity (HTML attributes) rather than adopter incentives (humans and vendors mandate React), i.e., that a verifier is a reason to *switch* runtimes rather than a feature note.
Cheapest days-scale test: run H1's two tests — shot/tree skill on existing React projects (1 day) and a closed-verb check linter over Alpine attributes (2–3 days) — plus H3's zero-code emission audit. All three predate any runtime code; together they answer whether the wedge is wanted, whether the closed vocabulary is the differentiator, and whether agents will even emit the grammar.
