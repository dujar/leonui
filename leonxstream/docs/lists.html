Lists

ui:each renders a keyed list from an array signal. The element carrying ui:each is a template: it is cloned per item (in DOM order), each clone gets the item in scope under the name you choose, and updates move as few DOM nodes as possible.

The three idioms in the example

  • Unique ids for local lists: keep a nextId counter in state — ids derived from list length collide after deletions.
  • Immutable updates: set todos = [ { id: nextId, t: draft }, ...todos ] replaces the array; removal is without(todos, td). Arrays are never mutated in place.
  • Empty state: a notice bound with ui:bind-hidden="todos.length != 0".

Because binds are fine-grained, toggling or removing one item touches exactly that item's bindings.

Drag to reorder

Add ui:sortable to the ui:each template and the list becomes drag-orderable. This is a Tier-3 primitive: you declare what — the primitive owns how. Drag previews the new order live; on drop the runtime writes the reordered array back as an immutable replacement, and the keyed render re-aligns. State, not the drag gesture, is the source of truth.

Rows get draggable, grab cursors and the dragging opacity from the shipped stylesheet. Implementation is HTML5 drag-and-drop (desktop); pointer/touch input and keyboard moves are roadmap. Because it is one attribute, ui check can see it, and it composes with everything else on the row — binds, verbs, per-row removal.
