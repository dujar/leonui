Verb reference

ui:fx="event: verb; verb; …" — handlers are lists of verbs from this closed catalog. Closed is the point: a fixed vocabulary the runtime can check, and an agent can learn in one page.

VerbEffect
set path = exprassign a signal (immutable replacement all the way down)
toggle pathflip a boolean
call M /url [with {…}] [optimistic: set …]fetch; body at event time; auto-rollback on failure
onfail toast '…'response gate — payload runs only when the last call failed
onsuccess toast '…'response gate — payload runs only when the last call succeeded
toast exprtransient message in a role=status host
nav '#screen-id'switch [data-screen] sections (+ view transition with ui:transition)
refetch cellre-run a remote cell's GET
prompt 'q' into pathask, store the answer
confirm 'q'guard — aborts the remaining verbs if declined
focus '#sel'move focus
reset '#form'form.reset() + re-sync ui:model paths
delay mspause the verb list

Expression whitelist

Literals · dot paths · .length · + - * / % · == != < > <= >= · && || ! · ternary · array/object literals with spread · and exactly these pure operators: without(arr, item), contains(str, sub), first(arr), sortBy(arr, key). Everything else is rejected with a named error, and every warning lands in window.__ui.warns.

Static checking

Because behavior is data on the tree, the runtime itself already lints what it can: unknown verbs, unknown ui:* attributes, undeclared signals and disallowed functions all produce named warnings in window.__ui.warns — typos are errors, never silent no-ops. (ui check will move this linting to build time; that is the roadmap's verification wedge — and the reason the grammar stays closed.)
